# WIMS 1.0.17

What changed since 1.0.16. Double-click **WIMS** on the Desktop or in the Start menu. A person still starts every transmit.

## Launcher

**One front door.** The Desktop icon, the Start menu entry, `scripts/start-wims.sh`, and the Windows WIMS shortcut open the same window.

**One launch path.** Operate from that window and Start-Wims-Solo share one start: the port check, the seat reading, the network default, the log and rules, the browser, the messages, and the details log.

**Updates.** The list shows every version, newest first. That includes published releases and version tags that have no release page of their own, so the versions after 1.0.10 are on the list. Hover a row to read that version’s notes. The date is this PC’s local day, so a tag from late in the evening stays on that day. The row tip includes the local time. **Check now** looks immediately. While the window is open, WIMS also looks in the background about every three hours, and never more often than every 15 minutes. **Install this update** and **Go back** are buttons. An install runs only from **Install this update**.

**Restart needed.** The site server reports the revision it loaded (`server_rev`). The window compares that with the copy on this PC. When both revisions are known and they differ, **Restart site server** is marked **Restart needed**: the server is running older code than what is installed. The title line shows the launcher revision (the code this window loaded when it opened) and the server revision (the code the site server loaded at start). After an install, the Updates list says **Restart server to finish the update**. A server that does not report a revision is left unmarked.

**Second double-click.** When the window is already open, another double-click un-minimizes it, raises it, and focuses it. The site console stays as it was. If that window does not answer, WIMS says what to do next. A port that is already in use says what to do next.

**Other tools and window size.** The closed window ends at the **Other tools…** checkbox. Checking it opens the extra tools underneath: screenshots, the desktop shortcut, the details log, the site URL, the Solo lab, and role cards, including home Operate and Inhibit. The window grows to fit, up to the screen, and then those tools scroll. Unchecking returns the window to the compact height.

## Log page, Log to use, and challenges

**Log** is its own page. It is the list of contacts WIMS checks for needed and already worked. The goal on Setup decides what counts. The log you picked stays put when the goal changes.

**Log to use** is that choice. The page shows the name, the path, the contact count, and the cutoff. A saved choice reloads without a restart. The goal suggests a log only when nothing is saved: a contest suggests the newest matching N1MM log; just operating, an award, or a custom list suggests the WSJT-X log. **Look again** finds a new contest file and leaves the chosen log chosen.

**Count only since** changes which contacts count as already worked. The logger’s file stays as it is.

- **Whole log** counts every contact.
- **Start now** counts contacts logged after you pick it. That cutoff is how a fresh challenge starts on the log you chose (for example, countries worked from this moment).
- **This year** counts contacts since January 1.

How often a station counts (once per band, and the other scopes on Setup) still applies inside that window.

When the chosen log is a WSJT-X file, WIMS reads each radio’s `wsjtx_log.adi` (or the one shared file, when you set one). The page says when a log is missing or unreadable. A WSJT-X log has no contest name or exchange, and the page says so when a contest goal is using that file.

**Check logs** on the Log page, and the Desktop **Check logs** icon, lead with a short summary. **Show details** lists contacts missing from a log. Copies of the same file — the same path, the same file on disk, or the same bytes — count as one log. The check groups by call, band, mode, and a three-minute window, so a large log finishes in about a second.

**Goal** on Setup is Contest, Award, Just operating, or Custom, then a second menu. DXCC, Worked All States, and VUCC use the log as the already-worked list. Just operating uses WSJT-X Colors. A checklist can add state or province, and call, each overall, per band, or per mode. County and callsign prefix show, and stay off. A contest choice saved by the older Setup menu is kept. Each control under Setup → Advanced has a short tip on hover and on the ? beside it.

## N1MM tab

The N1MM tab is the list of several stations at once. It shows on every page when two or more stations are heard. With one station, or none, the tab stays off the other pages. Opening the N1MM page directly still shows the tab selected, and the station list stays on the single-station view until more than one station is heard.

## Operate roster

**Message.** The roster keeps the text after the callsigns — a report, a sign-off (RR73 or 73), a grid, or leftover QSY or free text — and shows it in **Message**, just after Calling. Hover the cell for the full decode. A saved column set gains Message once. Transmit is unchanged.

**Max age.** The menu reads **15 sec**, **30 sec**, **1 min**, **2 min**, **3 min**, **5 min**, and **off**. The times are the same as before, labeled in seconds and minutes so “2 min” sits apart from the 2M band checkbox.

A seat you mark decode-only shows a decode badge, and Work on that row is refused. A TX-capable seat shows TX. Until you mark a seat, live instances stay TX-capable.

## Fixes

- A dial that is already the real frequency stays on that band. A Flex at 28.074 MHz stays 10 m. IF-to-RF mapping turns on only for seats you mark, by rig name or N1MM station, on Setup or the seat page.
- Work and Halt can leave this PC toward the WSJT-X that sent the decode, including when both programs are on this computer. When there is no route, the message is a plain sentence.
- A decode that arrives before the first status from that copy of WSJT-X stays off the roster. It remains in Band Activity.
