# WS Hub 1.0.20

What changed since 1.0.19. A Linux install from the download now knows its own build, so Restart site server no longer says the running copy is not the installed one. The call roster says when stations were heard but none are needed. A person still starts every transmit.

## Restart site server

**The installed copy is recognized.** A download does not include git, so 1.0.19 could not tell the running server from the copy on disk and wrongly said the server came back but was not the installed copy. Each release now records its build, and Restart site server compares that. When a build cannot be identified, the window says so instead of reporting an error.

## Call roster

**Empty list.** When no stations have been heard, the list still says **no decodes yet**. When stations were heard in the roster window (the current band and max age filters) but none are needed, it says how many, for example **20 decodes, none needed**. If the Show menu, or the band or max age filters, hid every row, it says **none match Show**. Hover the line for a little more detail.

## Settings folders (correction)

**The console's browser profile** is in `~/.local/state/wims`. That folder does not hold the window position. Seat profile stays in `~/.local/share/wims`. Settings stay in `~/.config/wims`. Installing or updating does not touch them.

## Installing from this page

**Linux.** Download `wims-1.0.20-linux-x86_64.tar.gz` and unpack it anywhere. Open the folder, open **scripts**, and double-click **Install WS Hub**. If the file manager asks once, choose **Allow Launching**, **Execute**, or **Run**. Then delete the download and double-click **WS Hub**.

**Windows.** Download `wims-1.0.20-windows-x86_64.zip` and extract it to `C:\WIMS`. Open `C:\WIMS\scripts\windows` and double-click **Install-Wims.cmd**. Then double-click **WS Hub**.
